# 가상 조선소 시뮬레이터 단계별 개발 계획

2026-10-27 기준 · 원본(편집용): https://claude.ai/artifact/LeD43VMpbkKVCpZ8Gcp4Ka · 설계: 도메인 모델 문서 · 이 원천을 받는 쪽: [데이터 플랫폼 계획](https://github.com/loozy5331/virtual-shipyard-data-platform/blob/main/docs/가상%20조선소%20데이터%20플랫폼%20단계별%20개발%20계획.md)

MVP는 10/26–11/7에 6단계(0~5)로 나눠 만들고, 11/8 게이트에서 "노이즈가 섞인 이벤트가 쌓인다"를 확인한다. 단계마다 이틀(약 4시간, 거제 하루 2시간 기준).

**진행 상황**: 0~5단계 완료, 게이트 뒤 6단계(설비 고장, ADR-010)와 7단계(자재 입고 지연, ADR-011), 10단계(컨테이너와 재발행 요청 디렉터리)와 11단계(재발행을 Kafka로, ADR-012), 12단계(재생 속도, ADR-013) 완료, 게이트 조건 확인(README "게이트 확인"). `main`에 `v0.1.0`(MVP), `v0.2.0`(게이트 뒤 작업), `v0.3.0`(6·7단계), `v0.4.0`(10·11단계). 게이트 뒤 작업으로 재발행과 대사(ADR-006)를 마쳤고, 출력 방식과 경계(ADR-007, Kafka 출력)와 대사를 플랫폼으로 넘기기(ADR-008)도 마쳤다. 아웃박스(CDC) 모양 출력(ADR-009)은 검토 중이다.

**계획과 달라진 점**
- 선종 3개(LNG선·VLCC·컨테이너선)와 실제 규모(블록 170~260개, 연 24척, 도크 5·선석 12)를 1단계에서 넣었다. 계획은 MVP에 선종 1개, 블록 8개였다.
- 도크를 세미 탠덤(배 한 척 + 배 반쪽, ADR-003)으로 바꿨다. 계약 납기는 도크 계획으로 잡는다(ADR-004).
- 엔진은 heapq 직접 구현 대신 SimPy로 만들었다(ADR-002).

## 원칙
- 단계마다 끝까지 돈다: 각 단계가 끝나면 명령 하나로 이벤트 파일이 나온다. 뼈대 먼저, 그다음 두껍게.
- 봉투는 0단계에서 고정. 이후에는 event_type과 payload 필드를 더하기만 한다(11/9부터 플랫폼이 이 계약에 기댄다).
- 완료 기준은 pytest로 확인한다.
- 단계 하나 = PR 1~2개, ADR은 결정이 생길 때만. 단계가 끝나면 README "만든 것"에 한 줄.
- 보정은 게이트 뒤로. 게이트에 필요한 것은 정확한 값이 아니라 노이즈가 섞인 이벤트.
- MVP에서 하지 않는 것: 화면, Kafka 등 브로커, 실시간 재생, 선종 2개 이상, 10개 공정 분리, 자재·사고·불량 이벤트. 출력은 JSONL.
- 밀리면 줄이는 순서: 4단계 포아송 수주 → 수주 목록 반복, 3단계 분포 → 균등분포. 5단계(노이즈)는 줄이지 않는다.

## 게이트 이후 (플랫폼 요청에 맞춤)

11/9부터는 데이터 플랫폼(별도 레포 `virtual-shipyard-data-platform`)이 주 작업이다. 시뮬레이터는 플랫폼 단계가 그 기능을 쓰기 전에 더한다. "쓰는 곳"은 플랫폼 계획의 단계 번호이고, 시기는 그 단계의 시작일에 맞춘다. 플랫폼이 무엇을 언제 쓰는지는 플랫폼 계획의 "이웃 레포" 표에 있다.

| 단계 | 시기 | 만드는 것 | 쓰는 곳 |
| --- | --- | --- | --- |
| 6. 설비 고장 | 완료(`v0.3.0`) | `equipment.status_changed`, 고장 중 작업 멈춤(ADR-010) | 플랫폼 1단계(첫 지표)·6단계 |
| 7. 자재 입고 지연 | 완료(`v0.3.0`) | 발주·입고 이벤트, 자재별 지연, 자재 없으면 작업 대기(ADR-011) | 플랫폼 9단계 |
| 10. 컨테이너와 재발행 요청 디렉터리 | 완료(`v0.4.0`, ADR-012) | sim·emitter·replay 이미지(Dockerfile), 재발행 서비스가 요청 디렉터리를 살펴 처리(처리한 파일은 옮김) | 플랫폼 4단계 |
| 11. 재발행을 Kafka로 | 완료(`v0.4.0`, ADR-012) | `emitter.replay --sink kafka`, ADR-007이 다루지 않은 경로 | 플랫폼 4단계 |
| 12. 재생 속도 | 완료(ADR-013) | 방출기가 `emitted_at` 간격을 실제 시간으로 줄여 보냄(`--speed`, 예: 시뮬 1일 = 실제 1분), 끝없는 정답 로그를 따라 읽기 | 플랫폼 5단계(감시)·7단계 |
| 8. 보정 v1 | 12월 이후 | Mendeley 블록 시간, 기사 마일스톤 → `params/v1.yaml` | 없음(시뮬레이터의 근거) |
| 9. 확장 | 12월 이후 | 선종 추가, 안전사고·용접 불량, 10개 공정 분리 옵션 | 플랫폼 선택 과제(QCD의 Q) |

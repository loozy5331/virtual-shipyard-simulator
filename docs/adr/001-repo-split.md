# ADR-001 레포 분리: 종이배 시뮬레이터와 코드를 나누고 개념만 옮긴다

- 상태: 확정
- 날짜: 2026-10-26

## 맥락

종이배 조선소 시뮬레이터(`virtual-paper-shipbuilding-factory-simulator`)는 생산관리 교육용 게임이다. 60일, 배 4척, 하루 단위 틱, 화면과 채점이 목적이다.
이 레포는 데이터 플랫폼에 넣을 원천이다. 끝없이 돌고, 분 단위 시각의 이벤트를 내고, 노이즈를 섞는다. 목적·시간 단위·출력이 모두 다르다.

## 결정

레포를 나누고 코드는 공유하지 않는다. 종이배 엔진에서 검증된 개념만 새로 구현한다.

| 개념 | 종이배 엔진 위치 | 이 레포에서 |
| --- | --- | --- |
| 공정 순서(선행 관계) | `rules.json` `stations[].after` | 공정 그래프 설정 `params/processes.yaml` |
| 블록 단위 흐름 | `block_plan`, `block_ids` | 블록 엔티티와 상태 전이 |
| 숫자는 데이터 파일에만, 엔진은 결정적 | `rules.json`, 난수표 | `params/*.yaml`, 시드 하나로 재현 |
| 엔진은 출력 방식을 모름 | `simulate(config) -> dict` | 엔진은 이벤트를 내고, 파일 쓰기는 따로 |
| 프로젝트 버퍼 | `buffer_plan` | 계약 납기와 계획 끝 사이의 버퍼 |
| 바쁜 날이 쌓이면 고장 | `breakdown.every_busy_days` | 가동 시간 기반 고장 확률(6단계) |
| 자재별 입고 지연 | `supply_delay_days` | 발주 이벤트의 지연 분포(7단계) |

## 결과

- 종이배 레포의 규칙이 바뀌어도 이 레포는 영향받지 않는다. 반대도 같다.
- 같은 개념을 두 번 구현하는 비용이 든다. 두 엔진의 시간 모델이 달라(ADR-002) 코드를 나눠 써도 얻는 것이 적다고 본다.

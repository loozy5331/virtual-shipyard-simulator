# ADR-002 시간 모델: 분 단위 정수 시계와 SimPy 이산 사건 엔진

- 상태: 확정
- 날짜: 2026-10-26 (5번 개정: 같은 날, heapq 직접 구현 → SimPy)

## 맥락

이벤트는 데이터 플랫폼에서 지연 도착·워터마크·구간 집계의 재료가 된다. 하루 단위로는 같은 날 이벤트의 순서와 지연이 보이지 않는다.
반면 한 척은 계약에서 인도까지 수년이 걸리고, 시뮬레이터는 끝없이 돌아야 한다. 시간 표현은 정확하면서 가벼워야 한다.

## 결정

1. 시뮬레이션 시계는 기준 시각(`epoch`, 설정값)부터 지난 **정수 분**이다. 부동소수 시각은 쓰지 않는다. 재현성과 해시 비교가 깨지기 때문이다.
2. 이벤트의 `occurred_at`·`emitted_at`은 ISO 8601, 초까지, 오프셋 `+09:00`이다(예: `2026-11-02T08:30:00+09:00`). 분 단위 시계라 초는 항상 `00`이지만 형식은 초까지 둔다. 방출기의 지연은 초 단위로 더할 수 있다.
3. 계획 값(`planned_end`, `contract_delivery_date`)은 일 단위 날짜(`YYYY-MM-DD`)다. 계획은 일로 세우고 실행은 분으로 기록한다.
4. MVP의 근무 달력은 **24시간 연속**이다. 소요 시간은 달력 시간(분)으로 정의한다. 주간 8시간·잔업·특근 달력은 보정 단계 이후 추가한다. 마일스톤 기간표(개월 단위)를 먼저 맞추는 것이 MVP의 목적이라, 근무 달력이 없어도 결과 기간은 같다.
5. 엔진은 SimPy(`simpy`)로 만든다. 배와 블록의 생애를 프로세스(제너레이터) 하나로 쓰고, 작업장은 작업장 번호를 담은 `Store`로 둔다(먼저 기다린 쪽이 먼저 받는다). 블록이 모두 모이기를 기다리는 일은 `all_of`, 6단계의 고장 중 작업 멈춤은 `interrupt`로 한다. 대기열·모으기·끊고 재개하기를 직접 만들고 테스트하는 비용을 아끼기 위해서다. 시계는 정수만 넘겨 `env.now`를 정수 분으로 유지한다.
6. 같은 시각의 사건은 SimPy 규칙(시각, 우선순위, 생성 순번)으로 정해져 결정적이다. 엔진은 일어난 순서대로 이벤트를 내고, `seq`는 entity_key별로 낸 순서대로 매긴다.

## 결과

- 시뮬 100년도 정수 분으로 약 5,300만이라 오버플로 걱정이 없다.
- 근무 달력을 넣을 때는 "작업 시간 → 달력 시간" 변환 함수 하나를 끼우면 된다. 이벤트 형식은 바뀌지 않는다.
- 자원 경합 로직은 SimPy가 맡고, 2단계의 용량·대기 테스트가 이를 확인한다.
- SimPy 프로세스는 제너레이터라 실행 중간 상태를 파일로 저장할 수 없다. 끊긴 실행을 이어 갈 때는 같은 시드로 처음부터 다시 돌리고 마지막으로 쓴 시각까지 출력을 건너뛴다(4단계).

## 검토한 대안

- `heapq` 이벤트 큐 직접 구현: 상태가 평범한 데이터라 저장·재개가 쉽고 같은 시각 순서를 직접 쥔다. 대신 대기열·모으기·인터럽트를 모두 직접 만들어야 해, 하루 2시간 일정에서 2~3일이 더 든다. 저장·재개가 꼭 필요해지면 다시 검토한다.

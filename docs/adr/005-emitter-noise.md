# ADR-005 방출기와 노이즈

- 상태: 확정
- 날짜: 2026-10-26

## 맥락

정답 로그(truth)에는 노이즈가 없다. 데이터 플랫폼이 다룰 원천은 실제 시스템처럼 늦게 오고, 순서가 뒤섞이고, 두 번 오고, 빠진다.
도메인 모델 문서는 노이즈 넷(지연 도착, 순서 어긋남, 중복, 누락)을 공장 이벤트가 아니라 방출기의 설정으로 두고, 파이프라인이 노이즈를 얼마나 복원했는지 정답과 비교해 채점하게 했다.

## 결정

1. **방출기는 엔진과 따로다**: `python -m emitter`가 truth를 읽어 emitted를 쓴다. 같은 truth로 노이즈 설정만 바꿔 여러 번 만들 수 있다.
2. **지연 도착**: `emitted_at = occurred_at + 지연`(초 단위). 지연은 대부분 보통(로그정규, 중앙값 몇 초)이고, 일부(`late_rate`)는 늦음(로그정규, 중앙값 몇 시간)이다. 늦음에는 상한(`max_hours`)이 있다. 통신 장애, 현장 단말의 일괄 전송 같은 일이다.
3. **순서 어긋남은 따로 넣지 않는다**: 파일은 도착 순서로 쓰므로 지연의 결과로 생긴다. 같은 개체의 `seq`가 뒤바뀌어 도착한다.
4. **중복**: `duplicate_rate`만큼 같은 줄(같은 `event_id`, 같은 `emitted_at`)이 재시도 간격 뒤에 한 번 더 도착한다. 보낸 쪽은 한 번 보냈다고 생각하는 at-least-once 재전송이다.
5. **누락**: `drop_rate`만큼 보내지 않는다. 누락된 이벤트는 중복되지도 않는다.
6. **출력**: `out/emitted/dt=YYYY-MM-DD/part-0.jsonl`, 도착 순서. 도착 = `emitted_at`(중복 사본은 + 재시도 간격). `dt`는 도착 날짜다. 그래서 늦게 온 이벤트는 `occurred_at`보다 뒤 날짜 파일에 들어간다(늦게 도착한 데이터).
7. **재현**: 이벤트마다 난수를 `{seed}:noise:{event_id}`로 따로 뽑는다. truth를 어떤 조각으로 나눠 읽어도 같은 이벤트에는 같은 노이즈가 붙는다. 노이즈 시드는 시뮬레이션 시드와 따로 준다.
8. **메모리**: 지연에 상한이 있으므로 도착 시각 순 힙에 담았다가, 지금 읽은 truth의 `occurred_at`보다 이른 도착을 내보낸다. 버퍼는 최대 지연만큼의 이벤트뿐이라 끝없는 truth도 흘려 처리한다.
9. **리포트**(`python -m emitter.report`): 정답과 비교한 실제 비율(누락·중복·늦음·순서 어긋남, 지연 분포)과, 방출 로그만 보고 찾은 수(`event_id` 중복, 개체별 `seq` 빈 번호)를 함께 낸다. `seq`로는 개체의 마지막 이벤트가 빠진 것을 알 수 없다. 뒤에 오는 번호가 없기 때문이다. 리포트는 이것을 따로 센다.

## 결과

- 플랫폼은 늦게 도착한 데이터, 중복 제거, 빈 번호 탐지를 실제처럼 다뤄야 한다. 정답이 있어 채점할 수 있다.
- 비율과 분포는 모두 가정(`params/v0.yaml`의 `noise`)이다. 실제 시스템의 값으로 바꿀 수 있다.
- 출처 시스템(ERP·MES·EAM)별로 다른 노이즈, 값이 틀린 이벤트(필드 오염)는 다루지 않는다.

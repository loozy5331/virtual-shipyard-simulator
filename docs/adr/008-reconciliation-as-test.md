# ADR-008 대사는 플랫폼에, 원천은 계약과 증명만

- 상태: 확정
- 날짜: 2026-10-27
- ADR-006 결정 1·6(리포트가 플랫폼 대역으로 대사)을 대체한다

## 맥락

ADR-006은 플랫폼이 없으니 리포트(`emitter.report`)가 플랫폼 대역으로 대사하고 재발행 요청 파일을 쓰게 했다. ADR-007은 착륙 구역부터 플랫폼이라는 경계를 그었다.
그런데 리포트는 실행 절차의 정식 단계라 대사가 시뮬레이터의 기능처럼 보인다. 플랫폼이 연습할 일(누락 찾기, 재발행 요청)의 답이 원천 레포에 있고, 요청 형식도 코드 안에만 있어 플랫폼이 기댈 계약으로 드러나지 않는다.
그래도 "원천의 계약만으로 누락을 모두 찾을 수 있다"는 증명은 원천이 가져야 한다. 그래야 마감 집계와 `seq` 규칙이 충분하다고 말할 수 있다.

## 결정

1. **원천이 내놓는 계약**: 개체별 `seq`(1부터 빈 번호 없이, 시스템을 가로질러), 마감 집계(ADR-006 결정 2~4), 재발행 요청 형식 `schemas/replay_request.json`(한 줄에 `{"entity_key", "seq"}`), 재발행 `emitter.replay`(ADR-006 결정 5).
2. **재발행은 요청을 스키마로 검증한다**: 형식이 틀린 줄이 하나라도 있으면 줄 번호를 알리고 아무것도 보내지 않는다.
3. **대사는 플랫폼의 일이다**: 리포트는 정답과 비교한 노이즈 실측만 낸다. 방출 로그만으로 찾기와 `--requests`는 뺀다.
4. **계약이 충분하다는 증명은 테스트로**: `tests/contract/test_recoverable.py`에 참조 대사를 두고 보인다.
   - 빈 번호와 마감 집계로 누락을 모두 찾고, `event_id`로 중복을 모두 찾는다
   - 찾은 누락은 요청 스키마를 통과하고, 재발행하면 누락이 0이 된다
   - 마감 집계가 없으면 끝 번호 누락은 찾을 수 없고, 개체는 마지막 이벤트 뒤 `lookback_days` 동안만 집계에 든다(계약의 한계)
   - 참조 대사는 명령줄로 내놓지 않는다. 대역으로 쓰이지 않게 하려는 것이다

## 결과

- 명령으로 "찾기 → 요청 → 재발행" 한 바퀴를 돌리는 시연은 없어지고, `uv run pytest tests/contract/test_recoverable.py`로 확인한다.
- 플랫폼은 스키마와 테스트를 보고 대사를 만든다. 리포트의 누락 수는 플랫폼이 찾아야 할 정답 개수로 쓸 수 있다(5년, 시드 0: 240개 = 빈 번호 181 + 끝 번호 59).
- 재발행에는 여전히 노이즈가 없다. 재발행도 빠지거나 늦게 하려면 노이즈 난수를 (시드, `event_id`, 시도 번호)로 뽑아야 한다. 지금처럼 (시드, `event_id`)면 처음 빠진 이벤트는 다시 보내도 또 빠진다. 플랫폼에 대사를 되풀이하는 루프가 생기면 다룬다.
